# コラムの品質基準

基準は、**A. SEO品質／B. デザイン品質／C. CV品質／D. コンテンツ品質**の4つに分かれます。それぞれ、`npm run column:check` が機械的に見るもの（自動）と、人が読んで・見て判断するもの（レビュー）があります。

- **エラー（✖）**：マージ不可。`status: review` 以降で必須になる項目は、下書き（`draft`）の間は注意として表示されます。
- **注意（△）**：直すか、残す理由をPRに書く。承認者が判断します。
- **レビュー**：Claude Code が自己レビューしてPRに結果を書き、承認者が最終判断します。

**本文が完成していても、必要な画像・CTA・プレビュー確認が終わっていなければ完成ではありません。**

## A. SEO品質

| 自動 | 内容 |
|---|---|
| ✖ | 必須項目：title / description / slug / service / keyword / author / status |
| ✖ | slug がファイル名と一致し、他の記事と重複しない |
| ✖ | 狙う検索ワードが他の記事と重複しない（自社記事どうしの順位の奪い合いを防ぐ） |
| ✖ | 公開する記事に `reviewer` と `publishedAt` がある |
| △ | タイトルが40文字を超える／検索ワードの語がタイトルに無い |
| △ | description が70〜130文字の範囲外 |
| △ | 本文が約2,500文字未満、H2が3個未満 |
| △ | 関連コラムへのリンクが2本未満 |

サイト側で実装済みのため記事ごとの作業は不要なもの：title（`記事タイトル｜KYUTE`）・meta description・canonical・OGP・X のカード・Article と BreadcrumbList の構造化データ・目次・sitemap（公開記事のみ）・下書きの noindex（`app/column/[slug]/page.tsx`、`app/sitemap.ts`）。

レビュー：

1. **タイトルと検索意図が一致しているか。** 検索結果で「自分の疑問に答えてくれそう」と思えるか。クリックしたくなる具体性（数字・対象・得られること）があるか。
2. **冒頭と各見出しの最初で、先に答えているか。**
3. **上位記事との差分があるか。** 上位記事を読んだ人が「これは初めて知った」と思える箇所があるか。
4. **見出しの階層が正しいか。** H2→H3の順で、見出しだけ読んでも流れが分かるか。

## B. デザイン品質

| 自動 | 内容 |
|---|---|
| ✖ | `status: review` 以降、アイキャッチ（`eyecatch`）がある（2026-10 の新ルール以前の記事は注意） |
| ✖ | アイキャッチのファイルが実在し、`public/column/<slug>/` にあり、JPG / PNG / WebP である |
| ✖ | アイキャッチが16:9、幅1200px以上、500KB以下（以前の記事は注意） |
| ✖ | 本文の画像に代替テキストがあり、ファイルが実在する |
| △ | アイキャッチが300KB超、WebP、alt が短い・タイトルと同じ |
| △ | 本文の画像が400KB超、`public/column/<slug>/` の外にある、外部サイトの画像 |
| △ | 図表・画像・動画が1つも無い |

レビュー（プレビューで見て判断）：

1. **アイキャッチの質。** テーマが一目で伝わるか。他の記事と見分けられるか。KYUTEのトーン（白・チャコール・黄色）に合うか。安っぽいAIイラストや汎用素材になっていないか。
2. **サムネイルとトリミング。** 一覧カード（スマホ幅約343px）で主題が分かるか。正方形に切り抜いても主題が残るか。
3. **図表の必要性。** 置いた図表がそれぞれ理解や判断を助けているか。逆に、比較・手順・数値を文章だけで説明している箇所が無いか。
4. **読みやすさ。** スマホで文字（図の中の文字も）が読めるか。文字だけの区間が長すぎないか。強調が多すぎないか。
5. **ブランドとの整合。** `docs/DESIGN.md` の色・書体・角丸から外れていないか。
6. **表示の崩れ。** デスクトップとスマホで、画像の欠け・表のはみ出し・CTAの崩れが無いか。

## C. CV品質

| 自動 | 内容 |
|---|---|
| ✖ | `status: review` 以降、`strategy`（reader / intent / stage / value / strength）がすべてある（以前の記事は注意） |
| ✖ | `strategy.stage` が learn / compare / decide のどれか |
| ✖ | 検討フェーズが compare・decide の記事に、本文中のCTA（`<!-- cta: id -->`）が1つ以上ある |
| ✖ | 本文中・末尾のCTAが `CTAS` に存在する。非公開サービスのCTAを他のサービスの記事で使っていない |
| △ | 本文中のCTAが4個以上 |
| △ | 本文中にサービスページ・制作事例へのリンクもCTAも無い |

レビュー：

1. **ターゲットとの一致。** `strategy.reader` の人が読んで、自分向けの記事だと思えるか。
2. **CTAの適切さ。** 本文中のCTAが、読者が行動を考えた直後にあるか。前後の文章とつながっているか。文言で「押すと何が得られるか」が分かるか。
3. **サービスへの導線。** 記事の内容から、自然にサービスページ・制作事例へ進めるか。リンクが機械的に挿入されていないか。
4. **信頼形成。** 料金・実績・進め方など、問い合わせ前の疑問のうち記事に関係するものに答えているか（[cv-design.md](cv-design.md#問い合わせ前の疑問に答える)）。
5. **問い合わせのしやすさ。** スマホで CTA が押しやすいか（高さ48px以上）、リンク先が正しいか。

## D. コンテンツ品質

| 自動 | 内容 |
|---|---|
| ✖ | `primarySources`（KYUTEにしか書けない一次情報）が1つ以上ある |
| ✖ | 公開する記事の本文に TODO・要確認・仮の文言が残っていない |
| ✖ | AIカジュアル面談・体験型会社説明会の記事に「必ず」「保証」「◯倍に」などの言い切りが無い。これらのサービスの記事は公開できない |
| △ | 数字があるのに `references` が無い |
| △ | 言い切り表現がある |
| △ | 「運動部のシゴト。」に触れているのに、自社メディアであると書いていない |

レビュー：

1. **一次情報が記事の中心にあるか。**
2. **事実が正しいか。** 数字・制度・他社の情報に出典があり、出典の内容と一致しているか。価格・サービス内容が `KYUTE/context/` とサービスページに一致しているか。
3. **公開してよい情報か。** 顧客名・数字・映像・画像に掲載許可があるか。自社メディアの実績を顧客実績のように書いていないか。AI生成画像を実写のように見せていないか。
4. **過剰な広告表現が無いか。** 売り込みが本文の主役になっていないか。検証中のサービスの効果を言い切っていないか。
5. **KYUTEらしい主張か。** 「面白さ」「消費から資産へ」など、KYUTEの考え方とつながっているか。
6. **読みやすいか。** [文章のルール](writing-rules.md)を守っているか。AIっぽい言い回しが無いか。

## 完成の条件

次がすべてそろったら「完成」としてPRを出します。

- [ ] `npm run column:check` のエラーが0、注意は直したか理由を書いた
- [ ] アイキャッチと構成表の図表が実ファイルとして入っている
- [ ] 本文中のCTAと末尾CTAが、`strategy` に合っている
- [ ] デスクトップとスマホでプレビューを確認し、スクリーンショットをPRに載せた
- [ ] A〜Dのレビュー項目を自己レビューし、気になる点をPRに書いた
- [ ] `npm run lint` と `npm run build` が通る

承認したら、`reviewer` に自分の id、`status: published`、`publishedAt` を入れてマージします。
