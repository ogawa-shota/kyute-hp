# コラムの品質基準

`npm run column:check` が自動で見るものと、依頼者が公開前に読んで判断するものに分かれます。人の承認はありません。

## 自動チェック（エラー＝マージ不可）

- 必須項目：title / description / slug / service / keyword / author / status
- `primarySources` が1つ以上ある
- slug がファイル名と一致し、他の記事と重複しない
- 狙う検索ワードが他の記事と重複しない
- 画像に代替テキストがある
- 公開する記事に `publishedAt` があり、本文に TODO・要確認が残っていない
- AIカジュアル面談・体験型会社説明会の記事に「必ず」「保証」「◯倍に」などの言い切りがない

## 自動チェック（注意＝依頼者が判断）

- タイトルが40文字を超える／検索ワードの語がタイトルにない
- description が70〜130文字の範囲外
- 本文が約2,500文字未満、H2が3個未満
- 本文中にサービスページへのリンクがない／関連コラムへのリンクが2本未満
- 数字があるのに `references` がない
- 言い切り表現がある

## 公開前に依頼者が読んで判断すること

1. **一次情報が記事の中心にあるか。** 上位記事を読んだ人が「これは初めて知った」と思える箇所があるか。
2. **検索意図に答えているか。** 検索した人の疑問に、冒頭と各見出しで先に答えているか。
3. **事実が正しいか。** 数字・制度・他社の情報に出典があり、出典の内容と一致しているか。
4. **公開してよい情報か。** 顧客名・数字・映像・社内事情に掲載許可があるか。
5. **サービスとの整合。** 価格・サービス内容が `KYUTE/context/` と一致しているか。検証中のサービスの効果を言い切っていないか。
6. **KYUTEらしい主張か。** 「面白さ」「消費から資産へ」など、KYUTEの考え方とつながっているか。
7. **読みやすいか。** 文が長すぎない、太字・箇条書きが多すぎない、AIっぽい言い回しがない。

問題がなければ「公開して」と頼みます。Claude Code が `status: published` と `publishedAt` を入れてマージします。
