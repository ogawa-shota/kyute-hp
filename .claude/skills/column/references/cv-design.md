# コラムのCV設計

コラムの成果は、検索流入ではなく**資料請求・相談・商談・受注**で測ります。記事を書く前に「誰が、どの段階で読み、読み終えて何をするか」を決め、その行動に必要な情報とCTAを記事の中に置きます。

## 1. CV戦略を決める

構成を考える前に、frontmatter の `strategy` を埋めます。`status: review` 以降は、未入力だとチェックでエラーになります。

```yaml
strategy:
  reader: 採用動画の外注を初めて検討している、従業員100〜300名の人事担当者
  intent: 採用動画の費用相場と、見積もりが高くなる条件を知って予算を決めたい
  stage: compare        # learn（情報収集）/ compare（比較検討）/ decide（発注直前）
  value: 費用の内訳と、金額が変わる条件を自分で判断できるようになる
  strength: 料金を公開しており、自社メディアで企画から撮影・編集まで実践している
cta: price-recruit-video  # 末尾CTA。省略するとサービスから自動で決まる
```

| 項目 | 決め方 |
|---|---|
| `reader` | 役職・会社規模・今の状況まで書く。「人事」だけでは構成が決まらない |
| `intent` | 検索した人が解決したいことを1文で。上位記事を読んで確かめる |
| `stage` | 下の表で決める。迷ったら検索ワードで判断する |
| `value` | 読み終えた人ができるようになること |
| `strength` | 読者がKYUTEに相談する理由。サイトで公開している事実（料金・自社メディアでの実践・制作体制）だけを書く |

| stage | 検索ワードの例 | 読者の状態 | 記事の役割 |
|---|---|---|---|
| `learn` 情報収集 | 採用広報とは／採用動画 効果／採用 ミスマッチ 原因 | 課題を整理している | 理解を助け、関連記事とサービスの考え方へつなぐ |
| `compare` 比較検討 | 採用動画 制作会社／採用動画 費用／採用YouTube 事例 | 外注先・方法を比べている | 判断基準と材料を渡し、KYUTEの料金・事例・資料へつなぐ |
| `decide` 発注直前 | 採用動画 外注／採用動画 見積もり／採用動画 依頼 流れ | 発注先を絞っている | 不安を解消し、資料請求・相談へつなぐ |

**キーワードを選ぶとき**は、検索ボリュームだけでなく商談につながる見込みを優先します。「採用動画 制作会社」「採用動画 費用」「採用動画 外注」のような `compare`・`decide` のワードを先に押さえ、`learn` の記事はそれらへの内部リンクの入口として書きます。

## 2. CTAカタログ

CTAは `lib/column/core.mjs` の `CTAS` にあるものだけを使います。**サイトで実際に提供しているものだけ**が載っています。新しい資料や診断ができたら、まず `CTAS` に追加してから記事で使います。

| id | ボタン | 行き先 | 向いている記事 |
|---|---|---|---|
| `price-recruit-video` | 採用動画の料金を見る | `/service/recruit-video#price` | 費用・相場・見積もり |
| `price-recruit-youtube` | 採用YouTubeの料金を見る | `/service/recruit-youtube#price` | 運用代行の費用・体制 |
| `works-owned-media` | 制作事例を見る | `/works` | 制作会社比較・事例・企画の考え方 |
| `download-recruit-video` | 採用動画の資料をもらう | `/service/recruit-video#download` | 採用動画全般（末尾の既定） |
| `download-recruit-youtube` | 採用YouTubeの資料をもらう | `/service/recruit-youtube#download` | 採用YouTube全般（末尾の既定） |
| `consult-general` | 無料で相談する | `/contact` | 採用広報全般、自社に合うか迷う読者 |
| `demo-*` | デモ・先行導入について相談する | `/contact?service=...` | 非公開サービスの下書きだけ |

記事テーマと優先CTAの目安：

| 記事テーマ | 本文中CTA | 末尾CTA |
|---|---|---|
| 採用動画の制作費用 | `price-recruit-video`（費用の表の直後） | `download-recruit-video` |
| 採用動画制作会社の比較 | `works-owned-media`（選び方の直後） | `download-recruit-video` |
| 採用動画の成功事例・企画 | `works-owned-media` | `download-recruit-video` |
| 採用YouTubeの運用方法 | `price-recruit-youtube`（体制・費用の話の直後） | `download-recruit-youtube` |
| 採用広報の基礎知識 | なし、または関連記事へのリンク | サービスの既定 |

「料金シミュレーション」「無料診断」「見積もりテンプレート」など、まだ無いものを書いてはいけません。

## 3. CTAの置き方

本文中のCTAは、Markdown に1行で書きます。カード型のCTAとして表示されます。

```md
<!-- cta: price-recruit-video -->
```

- **置く場所は、読者が次の行動を考えた直後。** 費用の表・比較表・事例紹介・選び方のチェックリストの直後が基本です。
- **冒頭付近**は、検索意図がそのまま行動に結びつく `decide` の記事だけ（例：「採用動画 見積もり」で、料金表へのリンクを導入の直後に置く）。
- **数は0〜2個、多くても3個。** 4個以上はチェックで注意が出ます。`compare`・`decide` の記事は1個以上が必須です。
- **前後の文章とつなげる。** CTAの直前の段落で「KYUTEの場合は〜」と1〜2文で接続し、CTAだけが浮かないようにします。
- 末尾のCTA（記事の下の濃いブロック）は自動で入ります。本文に重ねて書きません。

本文中のリンクも導線です。サービスページ・制作事例・`/download`・`/contact` へのリンクは、文脈に合う箇所に1つ入れます。「詳しくはこちら」ではなく、リンク先で何が分かるかを書きます（例：「[採用動画の料金表](/service/recruit-video#price)では、密着動画1本の価格と初回トライアルの条件を公開しています」）。

### 問い合わせ前の疑問に答える

`compare`・`decide` の記事では、読者が問い合わせ前に抱く疑問のうち、テーマに関係するものに本文で答えます。全部を詰め込む必要はありません。

| 疑問 | 答え方 | 使える材料 |
|---|---|---|
| この会社に頼むと何ができるのか | 支援範囲を具体的に書く | サービスページの内容 |
| 他社と何が違うのか | 比較の軸を示し、KYUTEがどこに当てはまるかを事実で書く | 料金公開、1日密着の企画、自社メディアでの実践 |
| どんな制作実績があるのか | 自社メディアの動画を「自社メディア」と明記して見せる | 「運動部のシゴト。」（顧客実績ではない） |
| 費用はどのくらいか | 公開している料金を出典つきで書く | サービスページの料金表 |
| 自社に合うか | 向いている会社・向いていない会社を書く | 一次情報 |
| 相談すると何が得られるか | 相談の中身を書く（ヒアリング、進め方の提案） | `/contact` の記載 |

顧客の社名・成果数値・映像・画像は、掲載許可が確認できたものだけを使います。「運動部のシゴト。」の再生数などは、**自社メディアの数字であることと集計日**を必ず書きます。

## 4. 効果測定

PVではなく、問い合わせ・商談につながった記事を評価します。

| 段階 | 指標 | 測り方 | 状態 |
|---|---|---|---|
| 集客 | 検索表示回数・検索CTR・自然検索流入 | Google Search Console（ページ別） | 外部設定。プロパティの確認状況を要確認 |
| 集客 | 記事ページのPV | Vercel Analytics（導入済み） | 実装済み |
| 記事内行動 | CTAクリック数・クリック率 | Vercel Analytics のカスタムイベント `column_cta_click`（`slug`・`cta`・`position`=inline / end / site） | 実装済み。カスタムイベントはVercelのPro以上で集計される |
| 記事内行動 | サービスページへの遷移率 | `column_cta_click` の `href` と、Vercel Analytics の遷移 | 実装済み（同上） |
| 記事内行動 | スクロール到達率 | 必要になったら追加（GA4 等） | 未実装 |
| 事業成果 | 資料請求・問い合わせ数、問い合わせCVR | 資料請求の通知メール・Googleフォームの回答を、流入記事つきで管理表に記録 | 運用で対応。フォーム送信に流入記事を自動で付ける仕組みは未実装 |
| 事業成果 | 商談化数・率、受注数・率 | 同じ管理表に商談化・受注を追記 | 運用で対応 |

**記事の評価のしかた（月1回）**

1. Search Console で、記事ごとの表示回数・CTR・平均掲載順位を見る。
2. Vercel Analytics で、記事ごとのPVと `column_cta_click`（本文中・末尾それぞれ）を見る。CTAクリック率＝クリック数÷PV。
3. 管理表で、その記事を経由した問い合わせ・商談・受注を数える。
4. 優先して直す記事の順番：問い合わせはあるが流入が少ない記事（タイトル・description・アイキャッチを改善）→ 流入はあるがCTAクリックが少ない記事（CTAの位置・文言を改善）→ CTAクリックはあるが問い合わせにならない記事（遷移先との接続を見直す）。

問い合わせを記事単位で自動計測するには、サイトのフォーム送信に流入記事を付ける実装と、Googleフォーム側の設定が必要です（`docs/COLUMN.md` の「効果測定」に残課題として記載）。
