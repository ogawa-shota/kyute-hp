# 内部リンク設計

更新日：2026-10-16。目的は、検索から来た読者が判断に必要な情報をたどり、資料請求・相談へ進めること。リンク本数自体を目標にしない。

## 実装済みの主な関係

| 起点 | 遷移先 | リンクを置く意味 |
|---|---|---|
| 共通ヘッダー・フッター | 2サービス、事例、コラム、会社、資料、相談 | サイト内の主要情報への入口 |
| トップ | サービス、事例、最新記事、料金、資料、相談 | 課題から選び、確認へ進む |
| サービス一覧 | 2サービス詳細 | 提供範囲を選ぶ |
| サービス詳細 | 同ページ料金・資料、事例、相談 | 条件を確認して行動する |
| 事例一覧 | 自社メディア、YouTube、採用動画制作 | 見た動画からサービスを理解する |
| コラム一覧・カテゴリ | 公開記事 | 読みたい判断材料を選ぶ |
| 記事パンくず | トップ、コラム、公開カテゴリ | 上位の情報に戻る |
| 記事本文 | 文脈に関連するサービス・出典 | 主張と条件を確かめる |
| 制作会社比較記事の費用説明直後 | `/service/recruit-video#price` | 自社に合う費用条件を具体的に確認する |
| 記事末尾 | サービス資料・無料相談 | 次の検討段階へ進む |
| 記事著者欄 | `/about` | 運営会社を確認する |
| 関連記事 | 同じカテゴリの公開記事（存在する場合） | 追加の疑問を解消する |

コラム本文のCTAは `lib/column/core.mjs` のCTASだけを使う。今回、比較記事の費用説明直後へ既存 `price-recruit-video` を追加した。料金数値や保証のコピーは変えていない。

## 執筆時のルール

- リンクは通常の `<a href>` / Next.js `Link`。クリックイベントだけで遷移させない。
- アンカーには遷移先と目的を表す言葉を使う。「こちら」や同じ検索語の反復を避ける。
- 比較記事は、比較条件 → KYUTEの公開料金・制作例 → 資料請求の順が自然。読み始めから同じCTAを何度も出さない。
- 一次情報に関係するサービスリンクを本文に少なくとも1か所置く。関連コラムは存在し、読者の疑問に答える場合だけ置く。
- 未公開・未来公開・非公開サービスの記事へ本番からリンクしない。公開ページを増やす際は一覧・カテゴリ・文脈の合う記事からの入口を同時に確認する。
- 外部出典のうち一般的な参考資料に一律nofollowを付けない。広告・対価・アフィリエイトの関係があるリンクは関係を示す属性と表示を別途検討する。
- コラムから広告LPをSEO目的の主要遷移先にしない。通常サービスページが公開条件を説明する先になる。

現在、公開コラムは1本のため、関連コラム2本未満の検査警告は妥当な例外。ダミー記事や意味の薄いリンクで消さない。公開記事が増えた時に、相互の文脈リンクを追加する。

## 確認手順

1. `npm run column:check` と `node scripts/test-seo.mjs` を実行する。
2. ローカルproduction buildを起動し、canonicalとsitemapに載ったURLが200を返すことを確認する。
3. 各記事の本文、料金CTA、資料CTA、著者リンク、目次を実際に操作する。
4. CTAのhashが実在するidへ到達すること、固定ヘッダーで重要情報が隠れないことをモバイルでも確認する。
5. 新しい記事は一覧・カテゴリから見つかること、孤立していないことを確認する。外部出典はHTML取得できないサイトがあるため、取得失敗を即リンク切れと断定しない。
6. Search Consoleのquery→URL、記事→サービスのクリック、資料請求完了、有効商談を別々に確認する。CTAクリックだけを成果CVとしない。

根拠：[Googleのクロール可能なリンクとアンカーテキストの指針](https://developers.google.com/search/docs/crawling-indexing/links-crawlable)。
