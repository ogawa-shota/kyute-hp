# コラムの書き方（チーム向け）

kyute.jp/column のお役立ちコラムは、Claude Code に依頼して作ります。目的は、検索から来た人事・経営者に資料請求・相談へ進んでもらうことです。Claude Code は本文だけでなく、CV戦略・アイキャッチ・図表・本文中のCTA・プレビュー確認まで行います。誰が頼んでも同じ品質になるように、手順と基準はリポジトリの中にあります。

- 手順：`.claude/skills/column/SKILL.md`（Claude Code が読む）
- CV設計（読者・検討フェーズ・CTA・効果測定）：`.claude/skills/column/references/cv-design.md`
- ビジュアル設計（アイキャッチ・図表・AI画像生成）：`.claude/skills/column/references/visual-design.md`
- 品質基準（SEO・デザイン・CV・コンテンツ）：`.claude/skills/column/references/review-checklist.md`
- 文章のルール：`.claude/skills/column/references/writing-rules.md`
- 記事の型：`content/column/_template.md`

## 一番大事なルール

**KYUTEにしか書けない一次情報（撮影現場での気づき、運動部のシゴト。の運用データ、支援で分かったことなど）が無い記事は書きません。** 一次情報が無いまま頼むと、Claude Code は書かずに「確認したい質問」を返します。

もう1つ、**本文ができただけでは完成ではありません。** CV戦略（`strategy`）・記事固有のアイキャッチ・本文中のCTA（比較検討・発注直前の記事）がそろわないと、`status: review` の時点で自動チェックがエラーになります。

## はじめに（1回だけ）

1. GitHub の招待を受け、`kyute-hp` に書き込めるようにする（取材メモを置く場合は `KYUTE` も）。
2. Claude Code をインストールし、`kyute-hp` と `KYUTE` を同じフォルダに並べてクローンする。
3. `content/authors/<自分のid>.json` が無ければ、最初の記事のときに Claude Code が作ります（名前・役割・経歴を聞かれます）。

## 依頼のしかた

### A：おまかせ（検索ワードと材料から一気に）

```
/column auto
サービス: 採用動画制作
キーワード: 採用動画 費用
CTA: （省略可。サービスから自動で決まる）
参考: https://...（省略可）
一次情報: 9月の撮影で、事前ヒアリングを60分に延ばしたら撮影当日の撮り直しが減った
画像: 生成OK（または「既存素材のみ」。書かなければ最初に聞かれます）
```

Claude Code は次の順で進め、PRに各工程の結果を載せます。

```
検索意図分析 → 競合・差別化分析 → CV戦略 → 記事構成 → ビジュアル構成 → 本文執筆
→ 画像・図解の制作 → 記事への組み込み → CTA最適化 → 推敲 → SEOチェック
→ デザインチェック・ブラウザプレビュー（PC・スマホのスクリーンショット）→ PR
```

キーワードは、検索ボリュームより商談につながる見込みを優先します。「採用動画 制作会社」「採用動画 費用」「採用動画 外注」のような、発注を検討している人の検索ワードを先に押さえます。

### B：じっくり（構成と文章を一緒に練る）

```
/column plan
テーマ: 採用動画が「見られない」本当の理由
読者: 採用動画をつくったが効果を感じていない人事
言いたいこと: 尺や画質ではなく、〜が原因だと思っている
材料: 〜社の事例、自分の撮影経験
```

方針メモ → 構成案（見出し＋画像・図解・CTAの構成表）→ 章ごとの執筆 → ビジュアル制作 → 推敲 → プレビュー確認、の各段階で止まって確認を求められます。最後は文章だけでなく、PC・スマホで実際のページとしての見え方を確認します。

### 既存記事を直す

```
/column 「採用動画 費用」の記事を、10月の新料金に合わせて更新して
```

## 一次情報の置き場所

- 公開してよい内容だけを記事に書きます。kyute-hp は public リポジトリなので、push した時点で誰でも読めます。
- 取材メモ・社内データの原本は、private の `KYUTE/content-sources/column/` に置いてください。Claude Code はそこも読みます。

## 公開までの流れ

```
依頼 → Claude Code が記事を書き、column/<slug> ブランチでプルリクエストを作る
     → 自動チェック（GitHub Actions）
     → Vercel のプレビューURLで下書きを読む（検索エンジンには載らない）
     → 編集責任者がレビューし、reviewer・status: published・publishedAt を入れてマージ
     → 公開（publishedAt が未来なら、その日に公開）
```

- 編集責任者：小川
- 自分の記事を自分で `published` にしないでください。

## 自動チェック

`npm run column:check` が、プルリクエストのたびに走ります。

| 種類 | 例 |
|---|---|
| エラー（マージ不可） | 一次情報が無い／検索ワードが他の記事と重複／公開記事に承認者が無い／画像の代替テキストが無い・ファイルが無い／検証中のサービスで効果を言い切っている／（review 以降）CV戦略が無い・アイキャッチが無い・16:9でない・重すぎる・比較検討や発注直前の記事に本文中CTAが無い／存在しないCTA・非公開サービスのCTA |
| 注意（承認者が判断） | タイトルが長い／description の長さ／本文が短い／関連リンクが少ない／数字に出典が無い／図表が1つも無い／本文中CTAが多すぎる／「運動部のシゴト。」が自社メディアだと書かれていない |

デザインの良さ・CTAの説得力・事実の正しさは、自動では判断できません。品質基準の「レビュー」項目を、Claude Code が自己レビューしてPRに書き、承認者が最終判断します。

2026年10月の新ルール以前に作った記事（`lib/column/core.mjs` の `LEGACY_SLUGS`）は、新しく必須になった項目が注意として表示されます。リライトのときに新ルールに合わせます。

`npm run column:keywords` で、今ある記事の検索ワード一覧が見られます。

## 非公開中のサービス

AIカジュアル面談と体験型会社説明会は、サイトでまだ公開していません（`lib/column/core.mjs` の `hidden: true`）。この2つの記事は下書きまで書けますが、公開はできず、カテゴリのタブも表示されません。公開するときは `hidden` を外します。

## CTA

CTAは `lib/column/core.mjs` の `CTAS` で管理します。サイトで実際に提供しているもの（料金表・制作事例・資料・相談）だけを載せています。新しい資料などができたら、先に `CTAS` に追加します。

**記事末尾のCTA**は `service` ごとに自動で決まり、`cta:` で変えられます。

| service | 末尾CTA（既定） |
|---|---|
| recruit-video | 採用動画の資料をもらう |
| recruit-youtube | 採用YouTubeの資料をもらう |
| ai-casual-interview | デモ・先行導入について相談する（※サービス非公開中。下書きのみ） |
| experience-briefing | デモ・先行導入について相談する（※サービス非公開中。下書きのみ） |
| general | 無料で相談する |

**本文中のCTA**は、Markdown に `<!-- cta: price-recruit-video -->` の1行を書くとカードとして表示されます。費用の表・比較・事例の直後など、読者が行動を考えたタイミングに0〜3個置きます。使えるidと選び方は `cv-design.md` にあります。

## 画像

- 新しい記事には、記事固有のアイキャッチ（1600×900のJPG、300KB以下）が必要です。`public/column/<slug>/` に置きます。
- `npm run column:eyecatch -- <slug> <元画像>` で、元画像を 1600×900 に切り抜き・圧縮して置けます。`--preview-dir <フォルダ>` を付けると、スマホの一覧サイズと正方形に切り抜いた確認用画像も作ります。
- AI画像生成は、Figma MCP の `generate_image`（KYUTEの Figma Proプランの Figma AI）を使います。追加の契約やAPIキーは要りませんが、1回ごとに Figma AI のクレジットを消費します。依頼に「画像: 生成OK」を書くと、確認なしで生成します。
- AI生成画像は、実在の社員・顧客・撮影現場の写真のように見せません。PRに「AI生成」と明記します。
- 図解はSVG（コード描画）か表で作ります。ルールは `visual-design.md` にあります。

## 効果測定

PVではなく、問い合わせ・商談につながった記事を評価します。指標と月1回の見方は `cv-design.md` の「効果測定」にあります。

| 指標 | ツール | 状態 |
|---|---|---|
| 検索表示回数・CTR・流入 | Google Search Console | 外部設定（プロパティの確認状況を要確認） |
| 記事のPV | Vercel Analytics | 導入済み |
| CTAクリック（記事・CTA・位置別） | Vercel Analytics のカスタムイベント `column_cta_click` | 実装済み。集計にはVercelのPro以上が必要 |
| 問い合わせ・商談・受注 | 問い合わせ管理表（流入記事・商談化・受注を記録） | 運用で対応 |

まだ無いもの：資料請求フォームの送信に「どの記事から来たか」を自動で付ける仕組み、Googleフォーム（`/contact`）側の流入記事の項目、スクロール到達率の計測。
